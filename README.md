# Knogra

**Chart the whole subject. One scene at a time.**

Knogra is a browser-based knowledge graph editor where every concept gets its own focused view. Navigate between nodes with smooth spatial transitions, illustrate them with AI-generated SVG pictograms, annotate with an assistant that understands your graph, and arrange layouts that reflect how you think — not just how the algorithm thinks.

## Getting started

Knogra runs at **[app.knogra.io](https://app.knogra.io)** — nothing to install, no account, no sign-up.

**See it in action.** [knogra.io](https://knogra.io/#videos) has a short video walkthrough.

**Start with a ready-made graph.** The [Library](https://knogra.io/#library) on knogra.io holds complete graphs across a range of subjects. Click **Open** on any card to load one straight into the app and explore it.

**Or build your own.** Double-click the canvas to create a node, drag from one node to another to connect them, and click a connected node to transition into its scene. That's the core loop — everything else builds on it.

**Finding your way around.** Right-click the canvas for the command menu, and press `F1` for the full keyboard reference. Your work saves itself to the browser's IndexedDB as you go; `Ctrl+S` downloads the entire workspace as a single `.json` file when you want a backup or want to share it.

**Read more.** The [blog](https://knogra.io/blog/) covers first steps, worked examples, and the thinking behind the graph-first approach.

## What you can build

- **Mind maps** — free-form thinking with structure when you need it. Not locked into rigid hierarchies.
- **Concept maps** — labeled relationships between ideas. See how concepts connect, not just how they nest.
- **Memory palaces** — navigate scenes spatially. Visual transitions build the associations that stick.
- **Equation collections** — LaTeX cheat sheets that live inside your knowledge graph. Math where it belongs.
- **Semantic networks** — nodes are concepts, edges are relationships. Classic knowledge representation, modern interface.
- **Nested mind maps** — mind maps inside mind maps: any node opens into a map of its own. Recursive mind maps, as deep as the subject goes.

## Features

- **Scenes** — a large graph is hard to take in at once, so you break it into focused views, each scoped to what matters now. They all draw from one connected graph, and keeping one tidy takes a click rather than an afternoon
- **Transitions** — moving between scenes is animated: shared ideas drift to their new positions instead of the screen jumping to something unrelated. You remember a concept by where it sat and how you reached it
- **Helicopter view** — the map above the scenes, built automatically from the graph: any concept at the centre, its neighbours around it, theirs beyond. Every connection keeps one fixed direction wherever you are, so moving from concept to concept never turns the map
- **Node and edge taxonomy** — nodes carry tags that categorize them across the whole graph: restyle every node with a given tag in one step, and the AI reads them as context. Edges carry labels and relationship types you define, each with its own styling; show or hide an entire type at once
- **Topology-aware AI** — the assistant reads your graph, nodes and connections both. Each concept keeps its own conversation, carrying only the context that concept needs, so nothing is buried in a scroll-back and no history is resent with every question. Ask it to grow the map and it suggests nodes and connections you'd missed
- **Notes & images per node** — every concept carries its own notebook: prose, LaTeX, pictures uploaded, found on Wikimedia or drawn by an image model from your description, and its own conversation with the assistant. A note sits on the idea it is about and is saved with the graph
- **Bring your own key** — AI runs on your own Gemini, OpenAI, Claude, or OpenRouter key. Requests go from your browser directly to the provider: no proxy, no relay, no account with us. (An Anthropic key must be scoped to a workspace when you create it in their Console.)
- **Paths & presentation mode** — any route through the scenes can be saved as a path: capture the one you wandered or compose one deliberately, then reorder it, add stops, drop what turned out irrelevant, and walk it again for revision, a lecture, or a story
- **Quiz mode** — hide a share of the nodes and find out how much of the map you can reconstruct; recalling a structure is a different thing from having read it
- **SVG graphics** — pictograms inside nodes, generated by a model from a description or brought in from anywhere; reusable presets keep one visual language across a graph
- **Design system** — 20+ node designs, 16 themes, background images, LaTeX equations rendered inside nodes
- **Layout system** — radial trees, circles, grids, alignment, distribution, rotation, spacing, and fold/unfold to collapse a branch
- **Node Manager** — a table view over every node in the workspace, for review and bulk edits when a graph outgrows the canvas
- **Markdown import / export** — import a Markdown file and the Mermaid diagram inside it becomes navigable drill-down scenes, with the comments, equations and notes that travelled with it. Export any graph back out to share or version it, or update an existing graph from an edited file
- **JSON save / load** — the entire workspace, content and design, in a single `.json` file

## Privacy

Your work stays in your browser — IndexedDB storage, works offline, no account required. AI calls go directly from your browser to your chosen provider — no proxy, no logging. No personal data, no third-party trackers, no cookies. The only data Knogra receives is anonymous, aggregate usage counts (app opens, workspace import/export) — simple tallies with no per-user identity. Full details in the [Privacy Policy](https://knogra.io/privacy).

## Tech stack

| Layer | Library |
|---|---|
| Graph rendering | [Cytoscape.js](https://js.cytoscape.org/) |
| Storage | [Dexie](https://dexie.org/) (IndexedDB wrapper) |
| Build | [Vite](https://vitejs.dev/) + TypeScript |
| Math rendering | MathJax (LaTeX in nodes) |
| Layout | Custom — radial auto-layout, geometric arrange tools, Mermaid fan layout |
| AI providers | BYOK — Gemini ([@google/genai](https://www.npmjs.com/package/@google/genai)), OpenAI, Anthropic, OpenRouter |
| Workspace files | Plain JSON; [JSZip](https://stuk.github.io/jszip/) read-only, for `.knogra` archives written before 1.6 |
| Telemetry | Upstash Redis via Vercel (anonymous counters only) |

No frontend framework — vanilla TypeScript throughout.

## Local development

```bash
npm install
npm run dev        # dev server at http://localhost:5173
npm run build      # production build → dist/
npm run type-check # TypeScript check without building
```

The app is served at the domain root and deploys to `app.knogra.io`. The marketing site (`knogra.io`) is a separate repo — `knogra-site`.

## Self-hosting

Deploy to Vercel by connecting this repo in the Vercel dashboard. Vercel auto-detects Vite, builds to `dist/`, and serves `api/ping.ts` as a serverless function.

For telemetry (optional): add an [Upstash Redis](https://vercel.com/marketplace?category=storage&search=redis) integration in Vercel. It injects the required env vars automatically:

```
UPSTASH_REDIS_REST_URL=
UPSTASH_REDIS_REST_TOKEN=
```

Without these, the app works fully — pings silently fail.
